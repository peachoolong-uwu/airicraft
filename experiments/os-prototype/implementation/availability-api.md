# Native availability and root waiting age

`os_observe` includes `facts.availability`. The first producer covers an already-open generic container and the player's 36 carried slots. It runs only for the integrated server; unsupported coverage is `{available:false}`. It is distinct from passive chunk/entity growth eligibility.

The source `native_stable_material_ticks` reports a clock identity, `throughTick`, a covered `fromTick`, a material `stamp`, and `gateRevision`. Only completed, advancing server ticks count. Begin/end material must agree, and authority transitions invalidate the interval immediately. Paused or partially completed ticks earn no time. Interrupted tick continuity changes clock identity. Unknown coverage retains the counter but sets `fromTick` and `stamp` to null.

The sampler reads server-owned inventory and the exact bound container handler. It checks player liveness, dimension, handler usability, ordinary authority, no active native effect, recent client supervision and lease heartbeat. Changed handlers cannot reuse a client window token. It never loads chunks, moves the player, or infers physical release. Item codecs are cached against copied stack equality; the bounded material fingerprint is recomputed each boundary. Registry synchronization excludes the sampling work.

The stamp binds world identity, lease, gate revision, inventory and window facts. The host validates its hash against the current frame before accepting progress. Bad counters, contradictory evidence, a regressing clock or a replacement clock within the same host epoch stop the feed and revoke its lease. Missing proof earns no time. Native evidence remains a scheduling hint; admission still captures and validates the actual operation again.

`ResourceLedger.allocationRevision` changes on stock protection, claim, delivery and supply allocation transitions. Identical target/delivery/supply retries and ordinary new captures do not change it. This detects an intervening allocation change even if the final state matches the old state. Observation invalidation and reconciliation also break continuity.

`NativeObservationFeed` combines the native proof with this host revision and `WorkService`'s observation generation. An operation must explicitly declare that this proof source covers its readiness; currently only `ContainerTransfer` does. Each credited request must retain its identity and be ready on both fresh capture bases, with unchanged host allocation and authority/material evidence. A new request cannot inherit another request's interval. Each root is credited once even when it has duplicate offers or participates in several compatible supply proposals.

Fresh recurring declarations arrive after the native capture. Retained desired requests earn elapsed age from native feasibility independently of that reevaluation; a slow VM cannot suppress another root's accounting. Execution selection still requires fresh authored declarations. Identical declarations retain age; withdrawal and recreation require new interval evidence. Repeated host pulses cannot count one capture twice. A gap of two seconds or more earns no inferred time; only the native covered suffix may count after a material interruption.

The scheduling policy still uses 2,400 eligible ticks for overdue FIFO and resets a serviced root on successful admission. This adapter does not establish general mixed-duty fairness: age while physical work owns the player, retained access contexts, and crop/sheep/tree/fishing feasibility need their own native coverage. The full workload and efficiency comparison remain separate qualifications.
