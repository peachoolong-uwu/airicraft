# Native driver protocol, version 1

This is the native boundary of the [handoff](../design/implementation-handoff.md), available only in Codex driver mode. The public transport is `airicraft agent tools call`. Its container adapter supports bounded standalone transfers and retained contexts in an already-open container on an integrated server. A standalone transfer closes its window; a context can serve independently identified transfers before closing. The [host context service](host-context-api.md) selects visits automatically; physical navigation/opening remain subsequent integration work.

## Request sequence

1. `os_observe {}` returns a versioned frame: native session ID, world/load epoch, capture sequence/ID, native monotonic time and age, relevant revision, client tick and available server tick. `facts.scope` names the currently open container; `facts.coverage` states what is known. Unopened containers are unknown. Observation never opens a GUI.
2. `os_lease {action:"acquire", hostId, epoch}` acquires a free player. Send `{action:"heartbeat", lease}` every second. Five wall seconds without renewal fences productive effects, including ones already queued on the server. `{action:"release", lease}` requests revocation and cleanup.
3. `os_submit {schemaVersion:1, id, captureId, operation:"transfer_container", arguments, payloadHash}` admits one operation. `id` is `{epoch, generation, sequence}`; sequence increases within the lease generation. Standalone arguments are exactly `{windowId, syncId, direction, itemId, quantity, allowance:{sourceItems, destinationItems}}`. Direction is `withdraw` or `deposit`; quantity and allowances are integers from 1 to 64, and both allowances must cover the quantity. A retained transfer additionally requires `contextId`, as described below.
4. `os_inspect {id}` queries the same request after a lost response. Resending that identity and payload is idempotent while retained. Acceptance is not completion. Preserve the request in the broker journal before submission.
5. `os_cancel {lease, id}` stops that request. Inspect until its receipt proves release, or retain unresolved ownership. Verified partial transfers remain in the world.

The SHA-256 fingerprint covers the UTF-8 JSON object `{arguments, captureId, operation}`, with recursively sorted object keys, preserved array order and explicit null fields, compact Gson JSON and HTML escaping disabled. Null and an omitted object field are distinct. Use the native `fingerprint` implementation as the cross-language reference; do not hash the transport envelope. The broker must verify its encoder against native test vectors before use. Native argument envelopes are bounded to 16 KiB and nesting depth 16.

Receipts retain the request's schema/operation/capture/hash basis. Effects report verified transferred and remaining quantities and server-confirmation status. Standalone release evidence requires the server handler and client GUI to be closed, the cursor empty, and held inputs, navigation, camera, item use, and fishing controls free. The final state and first stop cause cannot be changed by a late cancellation. A confirmation deadline of 30 wall seconds stops productive work but never proves release; late confirmation can still allow cleanup.

The runtime retains the active operation, any retained context, and the latest 256 settled receipts, plus a submission high-water mark. A new sequence advances that mark before operation preflight. Rejection after that point produces a retained `FAILED` receipt with phase `admission_rejected`, the original reason, and verified zero-effect accounting (`admitted:false`, release source `admission_not_started`). Querying the same identity recovers a lost rejection reply; corrected work needs a new sequence. Rejections before identity admission, including stale fences or conflicting hashes, remain protocol errors. The broker serializes ambiguous submissions. Evicted or unknown identities must never be replayed as new work on the assumption that they failed. Retention uses settlement order and cannot evict either active owner.

Only item IDs advertised in `facts.supportedItems` are admitted by this first adapter. They cover the reference crops, sheep products, birch, fishing outputs, supplies and basic tools. Bundles and other unsupported item types are rejected before admission: their slot-click hooks must not be mistaken for ordinary stack movement.

## Retained contexts

Submit `operation:"retain_container"` with exactly `{windowId, syncId}` against a fresh open-window observation. The context has its own request ID, receipt and opaque `effects.contextId`. Admission does not enter it. Native ticking retains the exact window and confirms server/client identity, an empty cursor and quiescent controls before reporting `phase:"context_ready"` and `effects.contextReady:true`. Its receipt remains unreleased throughout the visit. This operation adopts existing setup; it does not navigate or open a GUI.

Every transfer in that context uses a new submission ID, fresh capture and allowance, plus the exact `contextId` in its arguments. Missing, wrong, stale, entering or closing context identity rejects before effects. Nested contexts and unrelated operations cannot borrow the retained window. Only one ordinary operation runs at a time. Its successful or cancelled boundary can report `released:true` with `releaseEvidence.source:"server_handler_and_context"`: the cursor and controls are free for the context's next operation, while the window remains owned. An owned visible container screen is permitted at this boundary; an unrelated screen is not. This is release of that operation, not release of the player or context.

Every authority response has a separate nullable `context` receipt as well as `active`. `active:null` alone does not prove a free player. Context effects retain `completedOperations`; the host's scheduling policy enforces eight-operation/1,200-advancing-tick visit budgets, overdue precedence and outside turns. Native material availability may cover a confirmed ready context between operations, with its identity included in the material stamp. Entry, active child work and exit remain unavailable. This is evidence of a scheduling boundary, not player release or general mixed-duty feasibility; see [the availability contract](availability-api.md).

Cancel the context's request ID to end the visit. Native revocation first fences its current operation; that operation must finish cursor cleanup before context exit can run. Context closure requires both server/client closure and free controls. The context receipt then settles as `CANCELLED`, or `FAILED` if entry, an operation or cleanup failed. The first stop reason is preserved independently of any later failure; a later timeout or cleanup exception is additionally retained as `effects.cleanupFailure`, including after eventual release. Entry and exit each have a 30-second monotonic watchdog whose reporting continues during reflex handback waits. Expiry is failure evidence, never forced release. A reflex can fence already-queued cleanup, which resumes only after handback; expected fencing is not itself a cleanup fault.

Lease expiry, world transitions, shutdown and operator interruption revoke the context even between operations. A replacement host cannot acquire the player until both owners release. Journal the context's admission separately from each operation and retain it through final closure; settling a transfer must not settle the context. The effect broker permits child dispatch only in its own confirmed ready context, refuses unknown-receipt recovery while a context remains, and retains any context reported during lease revocation until its exact receipt proves release. The host context service coordinates automatic shared visits through that ownership boundary.

Retaining and closing a window perform no item clicks. An externally closed idle context can therefore report complete zero-item accounting after verifying physical release. Any uncertain item effects belong to the separate transfer receipt and still require reconciliation.

## Events and ownership

`os_inspect {sessionId, sinceSeqNo, limit}` reads ordered transitions after the supplied cursor. Limit defaults to 16 and is capped at 32. The buffer retains 512 events. The reply gives oldest/latest sequence, next cursor and an explicit `gap`; a gap invalidates complete-trace claims even when the affected receipt can still be queried. Unchanged reads and heartbeats do not fill the buffer.

Every response includes current authority. Native clock values belong to the reported session clock domain; do not subtract a broker clock from native nanoseconds. A broker uses native-reported age plus its own request round-trip time. The frame's server tick is a sampled clock, not proof of a particular effect's server tick.

Legacy gameplay dispatch and direct camera control are fenced while the lease or cleanup owns the player. Runtime reload is rejected during that ownership. Operator cancellation, reflex takeover, world leave and shutdown revoke queued effects immediately. The first slice does not automatically respawn once OS control has been activated. Read-only inspection remains available.

The affected source/destination slots and cursor are guarded at every step; unrelated slot changes do not invalidate cleanup. The active context is retained across lifecycle changes until release is verified. A detached owned server handler with an empty cursor can supply release evidence; an unreachable old server cannot. An external window closure sets `accountingComplete:false`: `transferred` then means only the verified prefix, and `remaining` is unverified work, not permission to retry. Refresh and reconcile stock before further consumption. Reflex policy configuration remains available during a hold.

## Qualification status

Deterministic tests exercise the public native and JSON boundaries with a fake Minecraft adapter. The real adapter uses vanilla slot-click behavior, validates the current server handler and exact expected stacks at each effect, and verifies client/server reconciliation. Compilation and simulated evidence do not establish live qualification; see [STATUS.md](STATUS.md) for the current gate.

Authority responses also expose `generation` when the lease is null. Recovery may establish non-admission only when the same epoch and generation are fenced, lease and active receipt are explicitly null, no retained context is reported, and the admission high-water mark is below the request sequence. A different generation, a mark at or beyond the sequence, missing required authority fields, or an active owner leaves an unknown receipt unresolved. Older version-1 peers omit the additive context field because they do not implement retained contexts. The original generation field and retained admission rejection were covered by 33 focused native tests and a live broker crash with a retained partial-transfer receipt; the never-admitted recovery branch remains simulated.
