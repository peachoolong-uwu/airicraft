Date: 2026-09-01  
Mode: external Codex driver (`scripts/codex-driver`)  
Objective: progress from a fresh survival world to the Ender Dragon, using only the exposed Airicraft agent tools for gameplay.

## Rules of this log

- Record non-fatal bugs with the evidence, workaround, and gameplay impact.
- Record missing but non-mission-critical harness capabilities separately.
- Do not treat a queued tool result as completed work; wait for its task state and events.
- A true blocker is a failure that prevents progress with every available exposed tool and has no safe in-game workaround.

## Non-fatal bugs / workarounds

- **Client world-time comparison is historical, not an open server-pause bug.** Evidence: pause snapshot at `clientTickId=914` reported `worldTime=318`; the one-step snapshot at `clientTickId=915` reported `worldTime=640`. Current interpretation: use `serverTickId` to measure server simulation and `pauseEpoch`/snapshot IDs to identify captures. The server-owned fix below supersedes the original client-only timing workaround; client `worldTime` is not a server-step assertion.
- **Historical navigation failure near, but not at, the requested destination; current defect unconfirmed.** Evidence: `navigate_to(284,67,-141)` started at `(65,67,-86)`, moved the player to `(281,65,-144)`, then ended `CALCULATION_FAILED` / `Path calculation failed` with an estimated 25 ticks remaining. The target was visibly in a small azalea/oak forest. Workaround: once within local-resource range, switch to the typed resource collector rather than retrying the same exact navigation goal. The recorded endpoint does not satisfy the requested exact goal. This proves that run failed, not that pathfinding incorrectly rejected a reachable target. The reached-goal reporting defect is fixed separately.
- **Exact break has no drop-pursuit contract; the historical timeout needs its own reproduction.** The original run reported `pending_timeout` after lower blocks were broken. Current exact-break execution confirms block changes, not inventory pickup; it does not proactively chase drops. A wrapper timeout alone does not identify an executor failure. `4c9c49ea` now selects the best valid inventory tool before every exact break. `a18d2b7b` maps `CALC_FAILED` to goal reached only when the active exact navigation goal is in fact satisfied. Workaround for the remaining issue: navigate to each known drop coordinate.
- **Automatic workstation selection cave preference is fixed in source; live terrain replay is pending.** In the original run, a carried crafting table was ignored in favor of a table around five blocks below the player, routing a safe surface player into a natural cave. `91f66673` makes a substantially lower found table ineligible when a portable table is carried, and its policy regression passed. Explicit surface placement remains the conservative workaround until that exact terrain is replayed live.
- **Tick-debug pause did not freeze hostile damage (fixed live 2026-09-04).** Historical evidence: after `pause` returned `paused: true`, `clientTickId=3963`, and `pauseEpoch=1`, the event stream recorded an arrow hit, fall damage, four zombie hits, death, and respawn, all at tick `3963`. The client-only tick gate let the integrated server continue running. Fix: `fd7d7743` makes the server own pause/step state and gates `MinecraftServer.tick`; the client now only coordinates frame capture. Live verification held `serverTickId=127` for 10 seconds paused and allowed exactly one tick (`128`) for one `step`. This freezes server-side mob AI, damage, and world simulation while preserving client-side snapshot rendering.
- **Blocked collection retained an active mine primitive (fixed live).** Evidence: wood collection declared `WAITING_FOR_PICKUP` / `target_missing` after collecting 4 of 16 logs, but its active mining task continued, moving from Y=67 to Y=44 before a hostile reflex. Cause: a blocked collection job still exposed its mine goal and retained its desired primitive request. Fix: only `RUNNING` collection jobs may expose or retain a primitive. Focused `EmbodiedAgentRuntimeTest` passed; hot-reload validation submitted a no-target one-log goal and confirmed `taskExecution=IDLE`, no goal ownership, and no movement.
- **Task lifecycle responses amplified full world evidence (fixed live).** Evidence: plain `agent tasks resume` and `agent tasks cancel` each emitted about 306k tokens, including the full known craft/smelt catalog, for a one-line lifecycle acknowledgement. Fix: the normal wrapper view now projects only lifecycle, compact reflex, compact task execution, and compact task fields; `missionExecution` remains verbose-only. `AiricraftCliMainTest` covers the omission, `:wrapper:test` passed, and the rebuilt CLI returned the bounded cancellation response against the live client. Commit: `b18376a`.
- **Reflex admission can change between calls; the unresumable drowning wedge is fixed in source.** Evidence: `agent status` reported `reflex.state=IDLE`, then an immediate `craft_recipe` was rejected as `reflex_active`. Later it stayed `AWAITING_PLANNER` for `DROWNING` with full air and no `holdId`. `48055ad9` now requires a hold identity for `AWAITING_PLANNER` and generates one for safety-only drowning holds; focused runtime tests cover resume from that state. This is expected action-time safety validation, not proof of a stale-status defect. Treat `reflex_active` as authoritative and retry only after the new reflex epoch resolves. Live drowning was not deliberately induced during the remediation pass.
- **Terminal navigation could retain a stale mutation gate (fixed live).** Evidence: after a `navigate_to` terminal `CALC_FAILED` and explicit cancellation, `agent status` showed no runnable job but `craft_recipe` was denied `active_task_in_progress` because its old `PAUSED_BY_REFLEX` execution snapshot was consulted before the terminal task/job states. - **`return_to_surface` no-support livelock is fixed in source.** Evidence: the original executor stayed `RUNNING` for more than 1,400 ticks at `towering:support_unavailable`, and its defaults ignored available oak planks. `db2da62d` adds overworld planks to the default filler set and fails deterministically after 100 consecutive unsupported ticks. Focused executor/argument tests passed, and the restarted live tool schema exposed the expanded defaults. This bounds failure; it does not discover distant shore.
- **Nearest surface search is too local after reflex displacement.** The search radius was widened from 12 to 16 blocks (`f53b49e`) after it missed proven village terrain about 15 blocks away; focused `SurfaceMemoryTest` passed. The radius is confirmed in current source; `SurfaceMemoryTest` tests refresh and standing policy, not that exact 15-block terrain. However, current `SurfaceMemory` also retains `lastSurface` and `lastGround` during the session; failure of all recovery options in this save has not been freshly reproduced.
- **Mob flee used blind movement and could enter water (fixed).** The reflex now selects loaded, dry, hazard-free standing targets that increase separation, prefers cover, reaches targets through short exact Baritone hops, and raises the configured water traversal cost while it owns the route. If water is already moving or submerging the player, it hands recovery to the existing water-aware safe-standing navigator before resuming ground flee. The deterministic water regression remains useful for exact terrain control, but live acceptance now runs in the untouched, naturally generated snowy-forest `pickup` world.

Those observations show damage, not a death in those two windows. Current security checks account for ranged line of sight and the flee selector prefers shelter. The earlier single-zombie success does not validate mixed ranged encounters. The original client is not currently paused; the old assertion that pause permits server damage is superseded by `fd7d7743`.
- **Displaced-ocean recovery is a historical failed attempt, not a verified current save-wide block.** The original run reported no crafting site, no adjacent placement support, and no usable surface target after displacement. The local radius and lack of cross-session memory/global shore discovery are confirmed. The saved terrain, inventory, remembered targets, and all exposed navigation alternatives have not been replayed together in this audit; do not assert that the save remains unblocked or blocked from the old snapshot alone.

### Next progression-focused reproduction: first-leg flee failure

Prioritize this narrow part of the ranged-reflex concern over a broad readiness redesign. In `SurvivalReflexRuntime.flee`, no selected target with `completedFleeLegs == 0` throws `safe_flee_target_unavailable`. `tickMobAttack` catches it and refreshes the snapshot without leaving ACTIVE. Escape escalation depends on completed legs or close contacts, not a deadline for this initial failure. `EmbodiedAgentRuntime.requireLivingPlayerForAction` rejects normal actuation while ACTIVE. Under persistent unsafe ranged exposure with no close contacts or viable initial target, this can keep crafting/resupply blocked while the reflex makes no escape progress.

This is a source-supported failure path, **not yet a reproduced current gameplay blocker**. Existing escalation tests cover completed legs and close contacts; they do not exercise repeated first-target selection failure in a world.

Reproduction acceptance: use a disposable controlled world, one visible skeleton outside melee range, low enough player health to select FLEE, and terrain with no eligible first flee target. Record the exact terrain, inventory and initial health; observe repeated `reflex.actuator_failed` with `safe_flee_target_unavailable`, the same ACTIVE safety epoch, zero completed legs, and a rejected crafting action. Include a control with an eligible escape target. Distinguish normal tick progress from bridge stalls, and stop before death using server-owned pause. Only then choose a bounded recovery change; do not simply release the safety gate into an unsafe situation.
