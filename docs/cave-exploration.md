# Cave exploration

`survey_cave` provides a compact observation for choosing the next short move. It casts 495 sparse first-hit rays, with a default distance of 12 blocks (allowed: 4–24). Results include up to eight visible standing candidates spread by direction, sixteen exposed ore blocks, twelve hazards, and local light levels. Returned positions count as fresh observations for exact block actions.

This is an alternative to repeated screenshots and hidden-block queries. It observes geometry around the player, including behind the current camera direction; it does not enforce darkness-limited eyesight. Sparse rays can miss small surfaces. Empty results do not prove absence, and `routeValidated: false` means a visible standing candidate may still be unreachable.

The planner prepares a shield, food, picks, torches and inventory space, remembers an entrance/return point, and disables path excavation and placement while traversing passages. It chooses short waypoints, surveys again, records useful junctions and tried branches, and restores its previous path settings afterward. For a chosen vein, use `mine_blocks` or `collect_resource` with `constraints.visibleOnly=true` and a small fixed scope. System 1 selects first-hit visible block sources, approaches them, mines and collects matching drops, then samples newly exposed surfaces. `break_blocks` remains useful for exact edits already in reach. Home stock is read from dated logbook observations and confirmed by opening storage.

Use `inspect_pathfind` to read current settings before changing them and after interruptions. With no arguments it returns seven movement/terrain settings; `{"names":["allowBreak","allowPlace"]}` requests a smaller set. Values and defaults use Baritone's serialized format. Up to 32 names may be queried, with no mutation. Cached tool descriptions are not live settings snapshots.

Initial acceptance covered surface observations, visible water, an existing underground workstation passage, and a successful return with digging/placement disabled. It does not yet establish natural-cave discovery, ore collection using only this interface, or reliable exploration of a large cave network.

`visibleOnly` defaults to false so explicit buried-resource excavation keeps working. When true, source discovery shares the survey's 495 first-hit rays at a distance of 24 blocks from the current player, then applies the fixed acquisition bounds. It may miss visible surfaces and ignores neither occlusion nor intervening fluids. It is independent of `surfaceOnly`. Matching dropped items remain eligible within scope. It does not change pathfinding permissions; allow local approach excavation only when intended, and restore travel restrictions afterward.

Example: `collect_resource {"resourceKind":"COAL","quantity":3,"constraints":{"center":{"x":217,"y":63,"z":392},"radius":8,"verticalRadius":6,"visibleOnly":true}}`. This specifies a local resource objective, not a guaranteed vein or route. An empty result only means the sampled view yielded no usable target; it does not establish that the surrounding rock contains no ore.

D068 live acceptance: a single visible-only three-coal request mined two surveyed faces and one newly exposed face, handled approach/pickup, and completed in about 7.6 simulation seconds without manual movement calls or rejected targets. The scope was radius 8 / vertical radius 6 around the lower landing. Local path excavation was permitted but inventory/durability show only the three ore breaks; headroom excavation was not needed in this case. This is a focused acquisition result, not proof of efficient traversal across arbitrary caves.
